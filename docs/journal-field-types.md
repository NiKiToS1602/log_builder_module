# Типы полей журнала

Шаблон задаёт столбцы журнала, их порядок и настройки. Форма «Добавить запись» собирает значения для одной строки по схеме конкретного журнала.

## Создание и настройка полей

1. На странице «Шаблоны» нажмите «Создать шаблон» или выберите «Редактировать» в меню существующего шаблона.
2. Укажите название шаблона и добавьте хотя бы один столбец. Для каждого столбца выберите тип и задайте его настройки. Столбцы можно переставлять и удалять. Их порядок виден в предпросмотре.
3. Сохраните шаблон. При создании журнала модуль сохраняет копию его столбцов и настроек. Последующие изменения шаблона применяются к новым журналам.

## Типы полей

| Тип | Настройки в конструкторе | Заполнение, проверка и отображение |
| --- | --- | --- |
| **Порядковый номер** | Тип «Порядковый номер» задаёт название «№». | При сохранении модуль присваивает номер по позиции строки в журнале. Первая строка получает номер 1. Прочерк недоступен. |
| **Текст** | Обязательность и пример в пустом поле. | Пользователь вводит произвольный текст. При сохранении пробелы по краям обрезаются. Формат и длина текста не проверяются, в том числе в журналах, созданных со старыми ограничениями. Пример служит подсказкой и не подставляется при сохранении. |
| **Число** | Обязательность, пример в пустом поле, минимум и максимум. Можно указать одну границу или обе. | Принимает целые, дробные и отрицательные числа. Ноль сохраняется как число. Значение за пределами диапазона сохраняется с предупреждением. В таблице ячейка подсвечивается и получает пометку «Вне диапазона». |
| **Дата** | Обязательность, ручной ввод или автоматическая подстановка текущей даты. | При ручном вводе пользователь выбирает дату в форме. В автоматическом режиме используется дата браузера на момент сохранения. В таблице дата отображается в формате `ДД.ММ.ГГГГ`. |
| **Дата следующей записи** | Обязательность. Дата вводится вручную. | Модуль проверяет, что дата существует в календаре. В таблице она отображается в формате `ДД.ММ.ГГГГ`. У активного журнала дата из последней сохранённой строки создаёт отметку в «Графике». |
| **Сотрудник** | Обязательность, ручной выбор или подстановка автора записи. | При ручном выборе используется справочник сотрудников. Ответственный за журнал предлагается по умолчанию, если он есть в списке. При автозаполнении используется выбранный автор записи. Сохраняется UID, а в таблице показывается ФИО из справочника. |
| **Филиал** | Обязательность, ручной выбор или подстановка основного филиала автора. | При ручном выборе филиал журнала предлагается по умолчанию, если он есть в списке. При автозаполнении используется основной филиал автора. Если у автора его нет, обязательное поле можно пропустить, поставив прочерк. В записи хранится ID филиала, в таблице отображается его название. |
| **Изображение** | Обязательность загрузки. | В поле можно выбрать один файл PNG, JPEG, WebP, GIF или AVIF размером до 1 МБ. Модуль проверяет тип и размер и читает файл. Изображение отображается в ячейке журнала. Рабочие вложения должны храниться на сервере с привязкой к записи. |
| **Подтверждение** | Правило «Кто подтверждает» и момент подтверждения — при вводе или после сохранения. | При вводе нужно выбрать допустимого сотрудника и отметить «Подтверждаю запись». В отложенном режиме строка сохраняется, а в ячейке появляется кнопка «Подтвердить». Модуль сохраняет ФИО, UID, роль и время подтверждения. |

В ранее созданных шаблонах и журналах может встречаться тип **«Да / нет»**. Он работает через выбор одного из двух значений.

## Как работает прочерк

- Галочка **«Поставить прочерк»** доступна у всех типов, кроме «№», включая обязательные и автоматически заполняемые поля. Галочка отключает ввод и проверки этого поля. При снятии галочки поле снова доступно.
- Модуль сохраняет пустое значение и отдельно отмечает явный пропуск в данных строки. И незаполненное необязательное поле, и явно пропущенное поле отображаются как `—`.
- Прочерк в поле подтверждения снимает требование подтверждения для этой ячейки. Если поле просто ожидает отложенного подтверждения, в таблице отображается кнопка «Подтвердить».
- Прочерк в поле «Дата следующей записи» убирает отметку, которую давало это поле. Даты из периодичности журнала продолжают отображаться. Если дата из последней строки совпадает с датой из периодичности, в списке дня журнал появляется один раз.

## Проверки при сохранении

1. **Шаблон.** Название шаблона и названия столбцов, кроме автоматически заданного «№», должны содержать текст. Для числа минимум не может быть больше максимума. Для правила «Выбранные сотрудники» нужно отметить хотя бы одного человека.
2. **Форма записи.** Браузер проверяет обязательные поля и допустимость ввода для чисел и дат. Текст из одних пробелов считается пустым. Для подтверждения при вводе обязательны выбор сотрудника и галочка «Подтверждаю запись». Когда форме нужен автор для автозаполнения или подтверждения, поле «Автор записи» обязательно.
3. **Подготовка данных.** Модуль обрезает крайние пробелы, преобразует числовой ввод в число и читает изображение. Если файл пуст, имеет неподдерживаемый тип, превышает 1 МБ или его не удалось прочитать, строка не сохраняется.
4. **Запись в журнал.** Модуль проверяет, что журнал активен, заполняет автоматические поля и повторно проверяет обязательность с учётом прочерков. Он проверяет корректность даты следующей записи, конечность числа и допустимость подтверждающего сотрудника. При ошибке строка не добавляется. Указанные границы числа влияют на предупреждение и подсветку, поэтому значение `9` при диапазоне от `2` до `8` можно сохранить. Сами значения `2` и `8` входят в диапазон.

## Кто может подтвердить запись

В шаблоне можно выбрать любого сотрудника, только автора записи, любого сотрудника кроме автора, менеджера, руководителя или нескольких конкретных сотрудников. Для правила **«Менеджер или руководитель»** достаточно одного подтверждения от любой из этих ролей. Для правила **«Выбранные сотрудники»** тоже достаточно одного подтверждения от любого отмеченного человека.

Право сотрудника проверяется при сохранении подтверждения. Уже подтверждённую или явно пропущенную ячейку нельзя подтвердить повторно. Журнал можно завершить, когда каждое поле подтверждения во всех строках подтверждено либо отмечено прочерком.

## Хранение рабочих данных

В текущем фронтенд-прототипе `localStorage` предназначен только для демонстрационных данных. После подключения бэкенда браузерное хранилище можно использовать для некритичных настроек интерфейса, например выбранного месяца в графике.

Сервер должен быть единственным источником достоверных данных для рабочих шаблонов, журналов и их настроек, расписания, записей, вложений и подтверждений. Рабочие данные запрещено сохранять в постоянном хранилище браузера, в том числе в `localStorage`. Фронтенд получает рабочие данные с сервера и отправляет изменения через API.

При сохранении записи сервер проверяет обязательность полей, допустимость прочерков и правила для соответствующих типов данных. При подтверждении сервер определяет сотрудника по авторизованной сессии, проверяет его право подтвердить запись и сохраняет ФИО, UID, роль и время подтверждения.
