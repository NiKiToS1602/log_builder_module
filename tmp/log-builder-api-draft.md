## Предлагаемые маршруты и правила — черновик

Все маршруты ниже предложены для согласования. JSON использует `camelCase`. Предлагаемый контекст запроса — серверная сессия модуля по ClearBarn Sign In. Организация, роль и доступные филиалы определяются на сервере. Фронтенд получает рабочие данные через API, постоянное хранилище браузера для них не используется. `locationId` — целочисленный ID из каталога, `employeeId` и `authorUid` — UUID `member_uid`. ID шаблона, журнала, столбца и записи выдаёт модуль. Календарные даты передаются как `YYYY-MM-DD`, время создания записи — строка ISO 8601 в UTC. [Спецификация входа](../docs/39_CLEARBARN_SIGN_IN_SERVICE_SPEC.md) · [Каталог](../docs/API_SPEC_parent_service.md) · [Типы полей](../docs/journal-field-types.md)

Для всех операций предлагается единая ошибка `{code, message, fieldErrors: [{field, code, message}]}`. `422` показывает подсказку возле поля, например `columns[1].min` или `values.<columnId>`. `401` предлагает войти, `403` сообщает об отсутствии доступа, `404` сообщает, что ресурс недоступен. При таймауте или `5xx` экран предлагает повторить действие. При ошибке отправки форма остаётся открытой с введёнными данными. Согласовать с Никитой формат ошибок, роли по операциям, политику `403/404` для ресурсов вне области доступа, механизм защиты POST при cookie-сессии и адрес тестового API.

### 1. Создать шаблон

**Черновик — `POST /api/v1/templates`.** Фронтенд передаёт `{name, description?, columns}`. Порядок массива задаёт порядок столбцов. Для каждого передаёт `name`, `type`, `required` и применимые настройки `placeholder`, `min`, `max`, `mode`, `signerRule`, `signerUids`. Для `sequence` сервер ставит имя «№».

**Ответ `201`.** `{id, version, status: "active", name, description, columns}`. Каждый столбец содержит серверный `id`; форма добавляет шаблон в список из ответа.

**Ошибки.** `422` — пустое название, пустая схема, недопустимый тип или настройка, минимум выше максимума, пустой список подписантов при `specific`. Предлагаемый `409` для совпадения названия применяется, если согласована уникальность.

**Согласовать.** Область уникальности имени, ограничения длины и числа столбцов, поддерживаемые типы и настройки, версии шаблонов. Для первого прогона достаточно `sequence`, `text`, `number` и `date` в режиме `auto`. Остальные типы проверить до включения в серверный редактор. Сохранение правок существующих шаблонов потребует отдельного решения по маршруту обновления и конфликтам версий.

### 2. Назначить журнал филиалу

**Черновик — `POST /api/v1/journals`.** Фронтенд передаёт `{templateId, templateVersion, name, locationId, employeeId, startDate, schedule}`. Для прогона `schedule = {"frequency":"none"}`. Юрлицо и отображаемые имена сервер берёт из каталога. Предлагается одна операция, которая создаёт активный журнал филиала и фиксирует копию схемы выбранной версии шаблона.

**Ответ `201`.** `{id, status: "active", templateId, templateVersion, schemaVersion, name, locationId, employeeId, startDate, schedule}`. По возвращённому `id` фронтенд переходит на `/journals/{id}`.

**Ошибки.** `422` — неверные дата или расписание, отсутствующие обязательные поля, неактивный или неподходящий ответственный, у филиала нет юрлица. `403/404` — филиал или шаблон вне области доступа. `409` — шаблон архивирован или версия изменилась. Форма предлагает обновить список и выбрать шаблон снова.

**Согласовать.** Может ли один филиал иметь несколько активных журналов одного шаблона, должен ли ответственный быть назначен именно в этот филиал, нужна ли активация черновика отдельной операцией. Для остальных вариантов периодичности согласовать формат `interval`, `weekdays`, `monthDays`, `lastDay`, `dates`, `times`, `endDate` и часовой пояс. Первый прогон использует кнопку прямого создания активного журнала.

### 3. Получить схему назначенного журнала

**Черновик — `GET /api/v1/journals/{journalId}`.** Фронтенд передаёт ID журнала в пути.

**Ответ `200`.** Метаданные из шага 2 плюс `locationName`, `legalEntityName`, `employeeName` и `columns` с ID, порядком, типами и настройками из снимка схемы. По этому ответу строятся заголовок, таблица и форма записи. Статус определяет доступность добавления записи.

**Ошибки.** `403/404` — показать, что журнал недоступен, и дать ссылку к списку. При временном сбое показать повтор загрузки. Для доступного закрытого журнала показать схему и строки в режиме просмотра.

**Согласовать.** Неизменность снимка и ID столбцов после назначения, правила просмотра закрытого журнала, хранение отображаемых имён при изменениях каталога. Если права чтения и записи различаются у пользователей одной роли, возвращать `canAddEntry` вместе со статусом.

### 4. Сохранить запись

**Черновик — `POST /api/v1/journals/{journalId}/entries`.** Фронтенд передаёт заголовок `Idempotency-Key` и тело `{schemaVersion, values, skippedColumns}`. Ключи `values` и элементы `skippedColumns` — ID столбцов из шага 3. Числа передаются числами, даты — строками, необязательное незаполненное поле — `null`. Явно пропущенный столбец передаётся только в `skippedColumns`; сервер возвращает для него `null` в `values`. Номер и автоматические значения вычисляет сервер. Автор берётся из сессии. Ручной выбор сотрудника в столбце остаётся значением этого столбца.

**Ответ `201`.** `{id, schemaVersion, authorUid, createdAt, values, skippedColumns, warnings}`. В `values` уже есть номер и автоматические значения. Число вне рекомендованного диапазона сохраняется и может вернуть предупреждение `{columnId, code: "OUT_OF_RANGE"}`. Фронтенд добавляет возвращённую строку в таблицу. Повтор с тем же ключом и телом возвращает ту же запись, включая её ID.

**Ошибки.** `422` — незаполненное обязательное поле без прочерка, неверный тип или дата, недопустимый прочерк для номера, неизвестный столбец при совпавшей версии. `409` — журнал закрыт, версия схемы отличается или тот же ключ используется с другим телом. При конфликте схемы перечитать её и дать пользователю сверить ввод перед новой отправкой. При таймауте повторить тот же запрос с тем же ключом. При отказе строка в таблице не появляется.

**Согласовать.** Правила прочерка для обязательных и автоматических полей, часовой пояс автоматической даты, атомарную выдачу номера, область и срок действия ключа повтора. Для расширения сценария отдельно согласовать загрузку изображений, подтверждение из авторизованной сессии, поддержку старого `boolean` и автозаполнение сотрудника и филиала.

### 5. Повторно открыть журнал и увидеть запись

**Черновик — `GET /api/v1/journals/{journalId}` и `GET /api/v1/journals/{journalId}/entries?limit=50&cursor=…`.** При первом чтении списка курсор опускается. Фронтенд заново загружает карточку и первую страницу строк, в том числе при прямом открытии URL.

**Ответы `200`.** Карточка из шага 3 и `{items, nextCursor}`, где строки имеют форму ответа шага 4, `nextCursor: null` означает конец списка. Предлагаемый порядок загрузки — новые записи первыми, с устойчивой сортировкой по `createdAt` и `id`; порядковый номер каждой записи сохраняется. Успешно записанная строка доступна для чтения сразу.

**Ошибки.** `403/404` — журнал недоступен. При сбое чтения строк показать ошибку в таблице и повтор её загрузки. При успешном ответе с пустым `items` показать «Записей пока нет».

**Согласовать.** Порядок показа в таблице, лимит и поведение при недействительном курсоре, гарантию чтения после сохранения.

## Критерии приёмки до 29.11.2026

- В чистом браузере авторизованный пользователь создаёт шаблон «Контроль температуры» со столбцами «№», обязательной «Температурой» с диапазоном 2–8, обязательным «Комментарием» и автоматической «Датой». Шаблон появляется в списке и выбирается в форме создания журнала после перезагрузки.
- Пользователь назначает журнал доступному филиалу с юрлицом, выбирает ответственного, дату начала и периодичность «По необходимости». После `201` открывается карточка по серверному ID. Порядок столбцов и их ID совпадают со снимком схемы. Изменение шаблона на стороне сервера после назначения сохраняет исходную схему журнала.
- Пользователь сохраняет температуру `9` и ставит прочерк в комментарии. Таблица показывает строку №1, дату и отметку «Вне диапазона». После обновления страницы, возврата из списка или открытия прямой ссылки в другом браузере с тем же доступом видны тот же ID записи, её значения и прочерк. Рабочие данные читаются из API, включая браузер без демоданных.
- Пустая температура без прочерка даёт ошибку поля и сохраняет введённые данные формы. Для проверки на сервере отправляется запрос без обязательного значения и ожидается `422`. При закрытом журнале попытка записи возвращает согласованный конфликт. Пользователь вне области филиала не может создать, прочитать журнал или записать строку по прямому ID. Истёкшая сессия ведёт к повторному входу.
- После таймаута повторяется отправка с тем же ключом. В API и после повторного открытия видна одна запись. При временной ошибке чтения таблица выводит сообщение и кнопку повтора, после успешной загрузки показывает сохранённую строку.
