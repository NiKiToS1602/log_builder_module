# Бэкенд конструктора журналов

Стартовое приложение Spring Boot 4.1.2 с Spring MVC и Actuator. Для локального запуска установите JDK 21 и укажите его в `JAVA_HOME`. Для первой сборки нужен доступ к Maven Central. Maven Wrapper входит в проект.

В IntelliJ IDEA откройте `backend/pom.xml` как Maven-проект или подключите этот файл в окне Maven уже открытого репозитория. Выберите JDK 21 как Project SDK и Maven Wrapper как версию Maven. После синхронизации запустите класс `LogBuilderApplication`.

Для запуска приложения подготовьте базу PostgreSQL и пользователя с правом создавать объекты в её схеме. По умолчанию приложение подключается к базе `log_builder` на localhost:5432 под пользователем `log_builder`. Параметры подключения задаются через `DB_URL`, `DB_USER` и `DB_PASSWORD`; в IntelliJ IDEA их можно задать в конфигурации запуска. При старте Flyway применяет миграции V1–V6, затем Hibernate проверяет соответствие моделей схеме.

Для локальных параметров также поддерживается файл `backend/.env` с ключами `DB_URL`, `DB_USER` и `DB_PASSWORD`. Он загружается при запуске из корня репозитория или каталога `backend` и исключён из Git. Переменные окружения имеют приоритет над значениями файла.

Для сборки и запуска из корня репозитория выполните в PowerShell:

```powershell
cd backend
.\mvnw.cmd clean verify
.\mvnw.cmd spring-boot:run
```

В другом окне выполните `Invoke-RestMethod http://localhost:8080/actuator/health`. У запущенного приложения поле `status` равно `UP`. Чтобы остановить сервер, нажмите Ctrl+C.

Swagger UI доступен по адресу http://localhost:8080/swagger-ui/index.html, спецификация OpenAPI — http://localhost:8080/v3/api-docs. Документация формируется автоматически по REST-контроллерам. По мере реализации API его операции будут появляться в Swagger UI.

## CRUD журналов (задача № 25)

Базовый путь — `/api/v1/journals`. Идентификаторы шаблонов и журналов передаются как UUID, идентификаторы филиалов — как целые числа.

| Запрос | Результат |
| --- | --- |
| `POST /` | Принимает `{name, templateId, templateVersion, locationId, responsibleUid?}`. Создаёт активный журнал по существующему активному шаблону, возвращает `201`, заголовок `Location` и карточку. |
| `GET /` | Возвращает `{items, page, size, hasNext}`. `page` начинается с 0, `size` по умолчанию 50 и принимает значения от 1 до 100. Порядок — по убыванию времени создания и UUID. `includeArchived=true` включает архивные журналы. |
| `GET /{id}` | Возвращает карточку `{journal, columns}` с метаданными и неизменяемым снимком полей, в том числе для архивного журнала. |
| `PUT /{id}` | Принимает `{name, responsibleUid, version}` и возвращает обновлённую карточку активного журнала. `null` или отсутствие `responsibleUid` снимает назначение. |
| `DELETE /{id}?version=0` | Архивирует журнал и возвращает `204`. Передайте текущую версию из карточки. Повтор архивации возвращает `204`. Записи, поля и аудит сохраняются. |

Чтение доступно ролям `owner`, `manager` и `employee`, изменение — `owner` и `manager`. Каждая операция ограничена организацией и действующим списком разрешённых филиалов из проверенного контекста. Недоступный журнал по прямому ID возвращает `404`. Устаревшая версия возвращает `409`, ошибки значений — `422`. Изменения журнала и аудит фиксируются в одной транзакции. Для аудита профиль пользователя должен присутствовать в локальном каталоге с заполненным именем.

Точка подключения аутентификации — атрибут текущего запроса `JournalAccess.REQUEST_ATTRIBUTE` типа `JournalAccess`. Его устанавливает серверный фильтр после проверки сессии и интроспекции по [спецификации ClearBarn](../docs/39_CLEARBARN_SIGN_IN_SERVICE_SPEC.md). При подключении cookie-сессии фильтр также должен проверять CSRF для изменяющих запросов. Фильтр ClearBarn в этом этапе отсутствует. Без подтверждённого контекста API возвращает `401`. Контрактные тесты устанавливают атрибут на серверной стороне MockMvc и используют временную PostgreSQL.

Тесты Maven используют отдельный временный экземпляр PostgreSQL. После сборки приложение можно запустить из каталога `backend` командой PowerShell `& "$env:JAVA_HOME/bin/java.exe" -jar target/log-builder-0.0.1-SNAPSHOT.jar`.
